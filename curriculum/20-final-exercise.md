# レッスン20：最終演習 — ToDo リストを作る

## 目標
書籍アプリ（レッスン11〜19）を見本にして、**ToDo リスト** を自分の力で一から作る。
新しいことは出てこない。どのレッスンの何を使えばよいかを考えながら組み立てること。

## 作るもの
| URL | 画面・処理 | ログイン |
|---|---|---|
| `GET /todos` | ToDo の一覧 | 不要 |
| `GET /todos/{id}` | ToDo の詳細 | 不要 |
| `GET /todos/new` | 登録フォーム | 必要 |
| `POST /todos` | 登録 → 一覧へリダイレクト | 必要 |
| `POST /todos/{id}/done` | 完了にする → 一覧へリダイレクト | 必要 |

## テーブル
`schema.sql` に追加する。
```sql
CREATE TABLE IF NOT EXISTS todos (
    id    SERIAL PRIMARY KEY,
    title VARCHAR(100) NOT NULL,
    done  BOOLEAN      NOT NULL DEFAULT FALSE
);
```
サンプルデータを3件ほど `data.sql` に入れること（テーブルが空のときだけ入れる書き方は レッスン11 を参照）。

## 課題

### 基本課題
1. **一覧**：`/todos` で全件を ID 順に表で表示する。完了したものは「済」、未完了は「未」と表示する。
2. **詳細**：一覧のタイトルをクリックすると `/todos/{id}` の詳細が開く。
3. **層の分け方**：Controller → Service → Repository の3層にする。コントローラにリポジトリを直接使わない。
4. **JPA**：リポジトリは `JpaRepository` を継承したインターフェースにする。
5. **登録**：`/todos/new` のフォームから登録できる。登録後は一覧へリダイレクトし、「○○を登録しました」と表示する。
6. **入力チェック**：タイトルは必須・100文字以内。エラーのときはメッセージを出してフォームを再表示し、入力値を残す。

### 発展課題
7. **404**：存在しない ID の詳細を開くと、専用の例外を投げて「見つかりません」画面を 404 で表示する。
8. **ログイン**：登録フォーム・登録処理・完了処理は、ログインしていないとできないようにする。
9. **完了ボタン**：一覧の未完了の行に「完了」ボタンを付け、押すと `POST /todos/{id}/done` で完了にする。
10. **テスト**：サービスの単体テストを Mockito で1つ以上書く（例：存在しない ID で例外になること）。
11. **期限**：`due_date DATE` 列を追加し、フォームで日付を入力できるようにする。期限が今日より前で未完了のものは赤字で表示する。

## 完成の条件（チェックリスト）
- [ ] コントローラに SQL や業務の判断（`if` による絞り込みなど）がない
- [ ] 注入するフィールドはすべて `private final`（コンストラクタインジェクション）
- [ ] POST のあとは `redirect:` している（F5 で二重登録されない）
- [ ] フォームは `th:action` で書かれている（ログインを入れても 403 にならない）
- [ ] 書籍アプリ（`/books`）も今までどおり動く
